# Language / i18n Configuration

关闭: [Issue #173](https://github.com/Chachamaru127/claude-code-harness/issues/173) — English version / how to set the global output language.

用户面响应（skill 输出、slash 命令、hook 消息）遵循显式会话或项目语言。**当未设置语言时，默认值为英语。** 仅当通过以下三种机制之一明确请求时，才使用日语。

本文档是 SSOT。`CLAUDE.md` Language 部分是指向这里的简短指针。README 在 "Language" 下链接到此处。

---

## How to switch language

有三种设置语言的方法。**解析优先级，从高到低：**

1. 每条消息的会话指令（您明确要求 agent 切换）。
2. 项目配置 `.claude-code-harness.config.yaml`（`i18n.language`）。
3. `CLAUDE_CODE_HARNESS_LANG` 环境变量。

如果均未设置，默认值为 `en`。请注意，项目配置优先于环境变量：当存在 `i18n.language` 时它获胜，而 `CLAUDE_CODE_HARNESS_LANG` 仅作为未设置它的项目的回退。

### 1. Project-level config — `.claude-code-harness.config.yaml`

对于跨会话持久化的按项目设置，请在运行时读取的 harness 配置文件 `.claude-code-harness.config.yaml` 中设置语言：

```yaml
i18n:
  language: en   # en | ja (default: en)
```

这适用于在项目内运行的每个 Claude Code 会话，语言指令在每个 turn 重新注入，因此响应保持配置的语言。将此文件提交以使选择对整个 repository 生效。

> 注意: `harness.toml` 是 `harness sync` 消耗的 v4/v5 构建源。它**目前不携带**运行时语言设置。请在 `.claude-code-harness.config.yaml` 中设置 `i18n.language`。

### 2. Per-session env var — `CLAUDE_CODE_HARNESS_LANG`

对于**不固定** `i18n.language` 的项目，在启动 Claude Code 之前导出环境变量，以为该会话选择语言：

```bash
export CLAUDE_CODE_HARNESS_LANG=ja
claude            # this session uses Japanese
```

或内联：

```bash
CLAUDE_CODE_HARNESS_LANG=ja claude
```

> 如果项目配置设置了 `i18n.language`，它会覆盖此环境变量。
> 要为单个会话覆盖固定的语言，请使用每条消息的会话指令（见下文）。

### 3. Per-message session instruction

要在会话中临时切换，请用自己的话告诉 agent：

```
> 以後は日本語で返答してください
```

```
> Please respond in English from now on.
```

这在会话剩余时间内优先于 `.claude-code-harness.config.yaml` 和 `CLAUDE_CODE_HARNESS_LANG`。

## What does NOT change

- 机器可读值（JSON schema 字段、契约裁定、日志键）无论语言设置如何都保持英语。
- 源代码标识符、文件名、commit hash、命令名保持原样。
- Conventional Commits 前缀（`feat:` / `fix:` / `docs:` ...）保持英语。

如果您在应该是机器可读的地方看到日语（例如 JSON 契约字段），请提交 Issue——那是 bug，不是 i18n 设置问题。

## Supported languages

| Code | Status |
|---|---|
| `en` | Supported (default) |
| `ja` | Supported |
| other (`zh`, `ko`, `de`, etc.) | 非正式支持——会话指令可以请求尽力而为，但 skill 输出可能包含英语 fallback |
