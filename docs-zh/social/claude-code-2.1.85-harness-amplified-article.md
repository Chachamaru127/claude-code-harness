## 采用标题

将 Claude Code 2.1.85 的改善变为 Harness"实运营强度"的故事

## 引言

AI 编码工具的更新，容易以"新功能增加了"结束。

但现场真正有效的是，功能本身不如**那个更新对每天的开发如何有效**。

本次 Claude Code 2.1.85 中加入的改善中，Harness 判断特别能放大价值的是 hooks 可以带条件了这一点。

Harness 没有原封不动地介绍，而是变成了**减少不必要确认同时保留安全自动批准**的形态。

并且，从 Claude 使用时和从 Codex 使用时，哪里立即有效，哪里下次应该加强，也整理了。

这篇文章中，用用户视角易懂地说明其中内容。

## 1. 本次的主题不是"追从"而是"放大"

Harness 想做的不是将 Claude 和 Codex 的更新原封不动地排列。

真正想做的是：
- 减少使用时的迷茫
- 先发制人地堵住容易发生事故的地方
- 不每次详细指示就能将初始动作倾向好的方向

也就是说，将更新的价值从"功能说明"变为"运营强度"是 Harness 的作用。

本次更新是那个想法最明显体现的例子。

## 2. 从 Claude 使用 Harness 的人，什么变了

### 2-1. 不必要的权限 hook 减少了，每天操作稍微变轻

本次 Claude Code 2.1.85 加入的是**可以给 hooks 附加条件**的功能。

hooks 是"某操作发生时自动运行的机制"。

之前，权限确认相关的 hook 有在较广范围运行的场景。最终什么都不阻止的情况下，也一度评价，所以容易产生细小的等待和噪音。

Harness 在此整理了：
- `Edit`
- `Write`
- `MultiEdit`

的编辑系常时检查，
- `git status`
- `git diff`
- `pytest`
- `npm run lint`
- `go test`

这样的**比较安全的 Bash 命令**，仅限于条件性运行 permission hook。

这样变化是：
- 无谓的 hook 启动减少
- 但安全命令的自动批准保留
- 不是粗略地允许危险操作

这种平衡。

不是显眼的变化。但每天多次使用的地方，所以慢慢有效。

### 2-2. 减少了 `MultiEdit` 动作偏差的感觉

编辑系工具有不仅 1 处编辑，还能汇总多处的 `MultiEdit`。

Harness core 侧已经注意到了 `MultiEdit`，但 hooks 侧的 matcher 还没完全对齐。

本次也对此对齐了，所以：
- 1 处编辑
- 多处汇总编辑

permission 处理不容易偏差。

用户视角来说，"为什么这个编辑处理不同"的违和感减少了。

### 2-3. 将 Claude 本体的改善连接到了 Harness 的安全性

本次最重要的一点是，Claude Code 的新功能不是仅仅"能用了"。

**在维持速度和安全性的同时变换为那种形态**。

只想快的话，减少 hook 就行。
只想安全的话，什么都加 hook 就行。

但那样在现场大多不顺利。

Harness 追求的是中间：

> 不是原封不动地接收 Claude Code 的更新，
> 而是变为每天开发中"不障碍的安全装置"。

本次做的正是这个。

## 3. 从 Codex 使用 Harness 的人，本次意味着什么

本次的直接实现对象是 Claude 侧。

所以对 Codex 用户来说，不是"今天 runtime 动作就变化"的更新。

但并不是就此结束。

在确认 Codex 侧官方 releases 的基础上，**下次真正有效的改善轴**被切出了。

本次整理的价值高的主要有 2 点：

### 3-1. `plugin-first workflow`

在 Codex 中 plugin 的处理也越来越强。

在 Harness 侧扎实地吸收这个的话：
- 是否引入不容易明白
- 缓存是否旧了不容易明白
- 哪个 plugin 有效不容易看见

这样的迷茫减少了。

Claude 侧 plugin 和 hook 的导轨很强，在 Codex 侧也整备这个入口的话，两者体验差能相当弥补。

### 3-2. `resume-aware effort continuity`

长作业中，"中途重启后，思考深度不知不觉下降了"的感觉有时会有。

Codex 的更新中，resume 时 model 和 reasoning effort 的处理比之前更好了。

在 Harness 侧也好好拾取的话：
- 长的修正
- 带验证的实现
- review 后的重启作业

品质不容易波动。

也就是说 Codex 侧本次的意义，不是"马上变化明显"，而是"下次在哪里加强就能接近 Claude 侧安心感的明确化"。

## 4. Claude 和 Codex 并列，现在的差异怎么看

易懂地总结，现在是这样：

### Claude 版 Harness

- 本次更新，马上体感变化
- 不必要的 hook 评价减少
- 安全的自动批准保留
- 编辑系工具的处理对齐

### Codex 版 Harness

- 本次马上 runtime 不变化
- 但下次加强的地方明确了
- plugin-first 和 resume continuity 是下次主战场

这个差异不是坏事。

Claude 侧 hook 强，所以先活用那里。
Codex 侧加强 plugin 和重启品质的导轨。

各自向强的地方加强，结果 Harness 整体变强。

## 5. 本次，实际 release 停止了的原因

这里坦白写。

本次的更新，准备了公开前提，但**实际 release 本身停止了**。

理由简单：
- 作业树中有未提交差分多
- `main` 的直近 CI 是 failure

这种状态下标签和 GitHub Release 推进，不合 Harness 的 release policy。

也就是说，不是"能出就出"，而是**先看是否处于可以出的状态**。

这个判断本身也和本次文章主题连接。

比起介绍更新，安全的发布更重要。

## 6. 总结

Claude Code 2.1.85 加入的 hooks 改善，单体也是好更新。

但 Harness 将其变为：
- 稍微变轻
- 稍微不迷茫
- 但安全性不下降

方向。

并且 Codex 侧整理了下次哪里加强真正有效。

比起加 1 个显眼的新功能，减少每天开发中挂碍的小噪音，长期使用更有效。

本次的更新是这种改善。

## 提问 / CTA

这种"将本体更新不原封不动地宣传，而变为运营强度"系的改善，地味但相当有效。

如果日常使用 Claude 或 Codex，
- 这里每次稍微挂碍
- 这里仅本体更新不够
- 希望 Harness 这样改

作为下次更新中高价值论点去看。
