# Plans.md Marker Reference

This document defines the canonical marker vocabulary for Plans.md files, the
preferred v1 English marker family, and the legacy read-compatible markers that
are retained only for backward compatibility with existing Plans files.

---

## Preferred v1 Markers (new output must use these)

These are the authoritative markers for all new Plans.md content generated by
skills, agents, templates, and humans.

| Marker | Who writes it | Meaning |
|--------|--------------|---------|
| `pm:requested` | PM / human | PM has requested this task |
| `pm:approved` | PM / human | PM has confirmed task completion |
| `cc:todo` | Worker / human | Task queued, not yet started |
| `cc:wip` | Worker | Task in progress |
| `cc:blocked` | Worker | Task is blocked; reason should follow |
| `cc:done` | Worker | Task completed (optionally followed by `[commit-hash]`) |
| `review:approved` | Reviewer | Review passed; no blocking issues |
| `review:changes_requested` | Reviewer | Review failed; changes required before proceeding |
| `release:ready` | Release skill | All gates passed; safe to release |
| `release:blocked` | Release skill | Release gate failed; do not ship |

> **Rule**: New output must only use the markers above. All generator code
> (skills, agents, scripts, templates) must write these forms and never produce
> legacy markers.

---

## Legacy Read-Compatible Markers (read-only; do not generate)

These markers are still recognized by the parser for backward compatibility with
Plans files that predate the English-marker migration. They must not be newly
generated by any skill, agent, script, or template.

| Legacy marker | Preferred equivalent | Notes |
|---------------|---------------------|-------|
| `cc:完了` | `cc:done` | Previous completion marker (Japanese) |
| `pm:依頼中` | `pm:requested` | Previous request marker (Japanese) |
| `pm:確認済` | `pm:approved` | Previous confirmation marker (Japanese) |
| `cursor:依頼中` | `pm:requested` | Cursor-era alias; never meant Cursor IDE support |
| `cursor:確認済` | `pm:approved` | Cursor-era alias; never meant Cursor IDE support |

### Important clarification: `cursor:*` markers

The `cursor:依頼中` and `cursor:確認済` markers originated in an earlier phase of
the project where a Cursor IDE integration was explored. That integration was
subsequently archived (see `archive/`). The presence of `cursor:*` read
compatibility **does not imply active Cursor IDE support**. Cursor IDE is out of
scope for v1 (see [PROJECT_SCOPE.md](PROJECT_SCOPE.md)).

## Migration Plan

### Current state

- Parser: reads both preferred and legacy markers.
- Generator: preferred markers are used in most places; some skills and the
  `workflow-guide` skill still reference legacy Japanese forms in documentation
  examples.

### Sunset path

| Phase | Action |
|-------|--------|
| **Now (v1)** | Read compatibility retained. No new legacy markers generated. |
| **Migration command** | Add a `harness plans migrate-markers` command (or `/plans-migrate`) that scans Plans.md files and rewrites legacy markers to their preferred equivalents, reporting a diff before applying. |
| **Write path removal** | Once the migration command exists, audit all skills/templates for any remaining generator code that emits legacy markers and remove those code paths. |
| **Parser removal** | After all known Plans.md files have been migrated, remove legacy marker recognition from the parser. This is a breaking change and requires a major version bump. |

### Finding generator code that still emits legacy markers

```bash
grep -rn "cc:完了\|pm:依頼中\|pm:確認済\|cursor:依頼中\|cursor:確認済" \
  skills/ agents/ templates/ scripts/
```

As of Phase 1.5, known occurrences are in documentation examples only
(workflow-guide, memory references, templates locale files). These are read-only
usage in explanatory tables and workflow diagrams, not active generation paths.
