# 採点設計規律 — DoD / acceptance_criteria の 3 層翻訳

Plans.md の DoD、または `create` が出す `acceptance_criteria` は、判定者（人間 / 別 agent のどちらでも）が同じ結果に辿り着ける形で書く。
判定法は「アルバイトの人がチェックリストで○×を付けられるか」。この 1 文がすべての判断基準になる。

## なぜ 3 層か

DoD 1 行に、検証可能な事実 / 仕上がりの質 / プロダクトとしての正しさを混ぜて書くと、どれも検証できない。
3 層に分けると、層ごとに担当できる判定者が変わり、曖昧さの逃げ場がなくなる。

| 層 | 判定するもの | 判定者 | 判定に使う根拠 |
|---|---|---|---|
| 機械○×の床 | 実行結果が仕様通りか | スクリプト / テスト / CI | exit code、テスト結果、字数 / 行数、grep 一致 |
| LLM 観点採点 | 構成 / 訴求 / 読みやすさが基準を満たすか | レビュー agent | 採点基準を列挙したチェックリスト |
| 本質 doc 参照 | プロダクトとして正しい方向か | 人間または spec 照合 | root `spec.md` / decisions.md の該当条項 |

3 層は Plans.md の DoD カラムに順番に並べる。1 タスクに全層が要るわけではない。
機械○×の床が無い DoD（人間の主観だけで判定する DoD）は、非 docs-only task では書かない。

## 層 1: 機械○×の床

Yes/No が実行で決まる条件だけを書く。

- テスト: `go test ./...` が exit 0、`bash tests/xxx.sh` が PASS を出す
- 字数 / 行数: SKILL.md が推奨 500 行以下、reference の見出しが 1 つ以上ある
- exit code: スクリプトの終了コードが 0
- grep 一致: 特定文字列が特定ファイルに存在する

「動く」「正しく実装されている」は機械○×の床ではない。何を実行して何が出れば○かを書く。

## 層 2: LLM 観点採点

機械では判定できないが、チェックリスト化すれば別の agent が独立に採点できる条件を書く。

- 例: 「読み手が結論に辿り着くまでに前置きが 2 文以内か」
- 例: 「専門語が初出の瞬間に正体を添えているか」
- 例: 「比較対象が 3 つ以上のとき表になっているか」

観点は「良い/ちゃんとした」のような一語評価にしない。判定できる粒度まで分解してから書く。

## 層 3: 本質 doc 参照

そのタスクが「プロダクトとして正しいか」は、機械にもチェックリストにも落ちない。
該当する正本（root `spec.md` の条項、`decisions.md` の Why、既存 skill の contract）を DoD に名指しで参照する。

- 例: 「spec.md の Execution Backend Contract に矛盾しないこと」
- 例: 「decisions.md D42 の shareable policy と矛盾しないこと」

参照先が無い場合は、DoD を確定する前に正本を作る（`create` の spec.md / Plans.md 二正本チェックに従う）。

## 曖昧形容詞の検出と翻訳

DoD / acceptance_criteria の下書きに次の語が出たら、そのまま確定せず 3 層のどこかに翻訳する。

`良い` / `ちゃんとした` / `適切な` / `わかりやすい` / `十分な` / `きれいな` / `しっかりした`

翻訳の手順:

1. その形容詞が指している対象を特定する（構成？速度？網羅性？表現？）
2. 対象が実行結果で決まるなら層 1 へ（例: 「十分な速度」→「p95 が 200ms 未満」）
3. 対象が読み手の受け取り方に関するなら層 2 へ（例: 「わかりやすい」→「専門語初出に正体を添えているか」）
4. 対象がプロダクト方針に関するなら層 3 へ（例: 「適切な設計」→「spec.md の該当章と矛盾しないこと」）
5. どの層にも翻訳できない場合、その DoD 項目自体が未成熟。ヒアリングに戻る

翻訳を促す一言（`create` / `add` で曖昧形容詞を検出したときに使う）:

> 「〇〇」は判定者によって基準がぶれます。何を実行すれば○か、または何を数えれば○かで言い換えられますか？

## worked example

Before（曖昧、判定不能）:

> DoD: レポートがちゃんとした内容で出力されていること

After（3 層翻訳済み）:

| 層 | DoD |
|---|---|
| 機械○×の床 | `bash scripts/report-gen.sh` が exit 0、出力ファイルが 3 セクション見出しを含む |
| LLM 観点採点 | レビュー agent が「結論→根拠→次アクション」の順で書かれているかを判定する |
| 本質 doc 参照 | `docs/rules/external-doc-style.md` の完成品分類（メタ説明を含まない）と矛盾しないこと |
